N+1 Problem & JOIN FETCH Resolution

Demonstrating the infamous Object-Relational Mapping (ORM) bottleneck. When fetching 500 posts with their comments, naive lazy loading executes 1 + 500 = 501+ distinct SQL queries. Spring Data's JOIN FETCH collapses them into exactly 1 single query.

Assignment 3

Ehcache 3 In-Memory Acceleration

Read-heavy analytics operations (calculating averages, sums, and rankings across tables) are computationally intensive. Using Spring's @Cacheable and Ehcache, subsequent requests are served straight from RAM in less than 3 ms.

CachedAnalyticsService.java Spring Cache 
@Cacheable("analytics")
public AnalyticsDto getAnalytics() {
    // 1st call: runs complex queries (simulated 500ms delay)
    // 2nd call: returns cached DTO instantly from Ehcache
    return analyticsService.computeAnalytics();
}
